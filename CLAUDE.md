# Boundless Spirit

A hard, movement-first 2D platformer (Celeste, Super Meat Boy) set in one connected forest.
A grey spirit wins back six colors, one per body part, by clearing one-run Spirit Rooms; each
color is a new movement ability that opens more of the map. About 2 hours, Windows first,
Godot 4.7 + GDScript. @Ben designs and builds levels; Claude writes most of the code.

The full design is in `docs/DESIGN.md`. Read the relevant section before starting a feature,
and update it when a decision changes (for example, record measured jump and dash reach there).

## Design in brief

- **Pillars:** movement is the game (no combat, stats, or inventory); color is earned; hard but
  fair (instant, cheap deaths); the forest opens up as abilities return.
- **Starting moves:** run (one speed), variable-height jump, crouch, push/pull blocks.
- **Colors, in fixed order:** 1 orange torso = Dash, 2 yellow back leg = Double jump,
  3 green back arm = Wall jump, 4 red front leg = Slide, 5 purple front arm = Climb,
  6 blue head = Spirit Phase.
- **Forgiveness everywhere:** coyote time 0.1 s, jump buffer 0.1 s, corner correction, hitboxes
  smaller than the art.
- **Death:** back in control in under 0.5 s. Main map respawns at the room entry or last
  checkpoint stone; Spirit Rooms always restart from their start. Rooms reset on death.
- **World:** the Hollow (grey hub) plus six regions and the Heart; 8–12 rooms per region.
  Color returns in layers, back to front: each Spirit Room's color fills one layer of the
  world and cascades 20% and 10% into the next two (table in `docs/DESIGN.md`).
- **No HUD during play:** the hero's body parts glow when their ability is ready.

## Build order

1. **Setup** (done): Godot project, folder layout, pixel-perfect settings, hero animations,
   grey hero standing in an empty room.
2. **Movement test room** (done; feel approved by @Ben at v1.0.3, may be retuned as levels
   arrive): starting moves, death/respawn, camera, all six abilities behind debug switches;
   level-building numbers are in `docs/DESIGN.md` and get re-measured after tuning.
3. **Vertical slice** (done at v1.0.5; @Ben played it start to finish): 9 rooms across the
   Hollow, Ember Grove, and the edge of Sunlit Meadow; room changes, checkpoints, autosave, the
   Spirit Room door and run, the orange unlock with the color cascade, a shortcut gate, retro
   SFX. It takes 4–6 minutes and plays easy, so later areas must climb in difficulty, and the
   room count behind the 2-hour estimate needs another look (`docs/DESIGN.md`).
4. **Content tools** (built at v1.0.9 on branch `content-tools`, waiting on @Ben's try): rooms
   that place themselves (`world_origin` on the room), the room template and
   `docs/BUILDING_ROOMS.md`, the editor World View, world color layers, the map screen, the full
   hazard, object, and creature set (with a gallery room), pause and settings menus. Done when
   @Ben can build a new room from the template without Claude.
5. **Regions 2–6.** Region 2, Sunlit Meadow, drafted at v1.0.21 on branch `meadow` (8 rooms west
   of Meadow Edge plus its Spirit Room, all about the dash; `docs/DESIGN.md`, "Sunlit Meadow as
   built"), waiting on @Ben's review and playtest.
6. The Heart and endings. 7. Optional content and polish. 8. Release.

## Project layout

```
res://
  game/      the game scene (main.tscn) and autoloads: game state and saving, world map,
             settings, sound, camera, backdrop
  player/    player scene, one script per movement state, tuning file
  rooms/     room.gd, terrain_layout.gd, _template/, _world_view.tscn, test/ (movement test
             room, gallery), and one folder per region
  entities/  hazards, objects, and creatures (one scene each), triggers, the Spirit Room gate
  ui/        letterbox, prompt, yes/no popup, pause menu, settings rows, map, speedrun timer,
             debug overlay
  shaders/   hero palette, world color layers, Spirit Room portal glow, spirit glow
  art/       generated from the asset packs by tools/build_art.py (don't hand-edit)
  audio/     sfx/ generated by tools/build_sfx.py
  tests/     headless tests: movement, game systems, hazards (the gallery), slice and Meadow
             playthroughs
tools/             Python scripts that build art/ and audio/ (standard library only; .gdignore)
docs/              design doc, room-building guide (BUILDING_ROOMS.md, for @Ben)
gamemaker-legacy/  the old GameMaker prototype and raw asset packs (reference only)
```

- `gamemaker-legacy/` has a `.gdignore`, so Godot never imports it. Art comes out of it only
  through `tools/build_art.py`; don't reference it directly.

## How the game fits together

- **Main scene** (`game/main.tscn`, `main.gd`, class `Main`): holds the hero, camera, HUD, and
  the current room, and swaps rooms as the hero moves. Entities reach it through
  `Main.instance` (null in tests that don't load it, so guard). It handles: room changes behind
  the letterbox (hero frozen, velocity kept), deaths and respawns, checkpoints, Spirit Room
  gates (`knock`: Interact at an entrance gate, the yes/no popup, then entering at the room's
  Start and remembering that gate; `leave_spirit_room` goes back to it) and timing (recorded
  quietly, no card), the color unlock (`collect_color`: the hero lands with input locked, then
  absorbs the color and the world's color cascades), play time, and autosave.
- **World map** (`game/world_map.gd`): built by reading every room scene under `rooms/`
  (except `test/` and names starting with `_`) without instantiating it: the id is the file
  name; `world_origin`, `region`, and `spirit_room` come from the root, the size from the
  terrain layout, plus checkpoint and entrance gate positions (for the map and leaving a
  Spirit Room). Spirit Rooms stand apart: each loads at the origin (`world_origin` ignored),
  never overlaps or connects by position (its edges are walls), and the map and World View
  leave it out.
  Rooms connect by position: leaving a room's bounds enters whichever room covers that spot,
  but only where that room is open (`WorldMap.solid_at`); its solid edge acts as a wall. No
  exit wiring. Falling out of a room with nothing below is a death. Adding a room is saving a
  scene in `rooms/`; overlaps print a warning and fail `tests/game_systems.tscn`.
  `rooms/_world_view.tscn` (`@tool`) shows every room in place in the editor.
- **Rooms** (`rooms/room.gd`, class `Room`): `world_origin` (tiles) and `region` on the root;
  children `Props` (back, z -20), `Terrain` (a `TerrainLayout`), `Decor` (front, z 1),
  `Hazards`, `Entities`, optional `Signs` and `Leaves`, and
  `Spawns` (Marker2Ds; `Start` is used for new games and Spirit Room restarts). On entry the
  respawn point is the spawn nearest to where the hero came in. `spirit_room` makes it one-run
  and timed. `Room` is `@tool`: in the editor it outlines its area and its neighbours' (red where
  they overlap), and its Room Size buttons call `resize_side()`, which adds or removes layout
  rows/columns (or sets `size_tiles` for a painted room) and, on the top or left, moves every
  placed node and `world_origin` so nothing shifts; one Ctrl+Z step via EditorUndoRedoManager.
  `size_tiles` (per axis, 0 = from the terrain) is read by `WorldMap` too. Run any room with F6 and the game starts in it. Room `.tscn` files are edited in
  the Godot editor and are the source of truth: change them in place, never regenerate them.
- **Terrain from text** (`rooms/terrain_layout.gd`, a `@tool` TileMapLayer): paints the room
  from its `layout` string: `#` grass, `%` rock, `=` plank (one-way), `.` empty (`^ v > <`
  still paint thorns, but rooms use `Thorns` objects instead so they can be moved and tinted). It picks every edge tile from the neighbors and repaints in the editor when the text
  changes. The layout's size is the room's size. Leave `layout` empty to paint by hand with
  the editor's terrain tools (the tileset has a Grass/Rock terrain set); the room is then as
  big as its painted tiles. Thorns sit on bare dirt: grass under a Thorns object is drawn as the
  plain dirt fill, with no grassy top or blades (`refresh_bare_soil`; moving thorns in the
  editor repaints it).
- **World color** (`game/world_color.gd`, `shaders/layer_color.gdshader`): six layers (sky,
  far hills, near forest, trees behind, front decoration, ground and gameplay) plus hazards,
  each drawn grey with its own color strength. `WorldColor.strengths()` turns the collected
  colors into strengths (color n fills layer n, +20% and +10% to the next two, adding up;
  hazards at least 10%) and `apply()` puts them in two global shader values that every room
  and the backdrop read. Rooms put `Props`, `Decor`/`Leaves`, `Terrain`/`Entities`, and the
  thorns (anything in the `hazards` group) on their layers when they load; anything in the
  `full_color` group (orbs, the doorway glow and runes, gate traces, the hint rune) keeps its
  color. Main animates a new color back
  to front (`_cascade`). The test room is full color.
- **Saving** (`game/game_state.gd`): JSON in `user://save_<slot>.json` with room, respawn
  point, colors, deaths, play time, flags (opened shortcuts), Spirit Room best times and
  clear deaths, and the gate to go back to from a Spirit Room.
  Autosaves on entering a room, at checkpoints, on a color, and when a shortcut opens. The game
  boots straight into slot 1 (no title screen yet). `-- --slot=N` on the command line picks
  another slot; automated runs use 9.
- **Menus** (all keys/gamepad, through `MenuList`, which polls input and works while the tree
  is paused): Esc opens the pause menu (`ui/pause_menu.gd`: play time, deaths, colors; Resume,
  Map, Settings, Leave Spirit Room inside one, Quit). Tab opens the map (`ui/map_screen.gd`:
  visited rooms drawn from their layouts in region colors, Spirit Rooms as diamonds, checkpoints
  as dots, the hero blinking; Move pans). Both pause the tree; UI and `Sfx` run with
  `PROCESS_MODE_ALWAYS`. `Main.can_pause()` blocks them during transitions, popups, and the
  color unlock. Visited rooms are saved (`GameState.visited`).
- **Settings** (`game/settings.gd`, autoload): music and sound volume (Music and SFX buses in
  `default_bus_layout.tres`), fullscreen, window scale, screen shake (camera `shake()`, on death
  and impacts), speedrun timer; saved to `user://settings.cfg` (never from headless runs).
  Control remapping is planned for the polish milestone.
- **Debug overlay** (`ui/debug_overlay.tscn`): hidden in the game, shown in test rooms. F3
  toggles it; while it shows, 1-6 toggle colors, 0 all, R respawn, F8 new game (deletes the
  save), F9 movement test room, F10 gallery. The version (bottom right) always shows.

## Other parts

- `project.godot`: 480×270 viewport, window sized at startup to the largest whole-number scale
  that fits the screen (3× on 1080p, 4× on 1440p; `game/settings.gd`), integer
  canvas_items stretch (so text is full resolution), nearest filtering, pixel snapping, 60 physics ticks, Compatibility renderer.
- Autoloads: `GameState`, `Settings`, `Sfx` (`game/audio.gd`: `Sfx.play(&"jump")` plays
  `audio/sfx/jump.wav` on the SFX bus; silent in headless runs).
- Input map matches the design doc's controls table (Interact is C / right bumper); physics
  layers: 1 world, 2 player,
  3 hazards, 4 spirit_barriers, 5 push_blocks, 6 vines.
- **Waystones in the world:** the Hollow clearing's stepped half-ring at the great tree's foot
  (six Ring stones, the Hollow stone in the middle); one Region stone beside each Spirit Gate
  (Ember Gate, Meadow Gate). `WorldMap` reads them from the room scenes like gates.
- **Player** (`player/`): CharacterBody2D with one script per state in `player/states/` (idle,
  run, crouch, jump, fall, dash, wall_slide, slide, ledge_grab, climb, spirit_phase, push, dead)
  and shared helpers in `player.gd`. `frozen` stops it (keeping velocity) for transitions and
  popups; `input_locked` lets it fall and land with no control (after touching an orb).
  Objects act on it through `launch()` (bounce flowers), `add_push()` (wind and waterfalls:
  sideways drift and vertical force, cleared each frame), and `smash_breakables()` (dashes
  break walls and carry on). Every movement number is in `player/tuning.tres`.
- **Shaders:** `hero_palette.gdshader` greys locked body parts by hue and dims spent ones (the
  body is the HUD); `spirit_glow.gdshader` draws the spirit.
- **Entities:** `checkpoint_stone` (`@tool`; its rune, a `Rune` on an uncarved stone, comes
  from its room's region via `REGION_GLYPHS`, so a region's stones match), `waystone` (`@tool`,
  class `Waystone`; `kind` Region, Ring, or Hollow and a `color`: awake once that color has
  returned (the Hollow stone always), glowing in it, and then Interact calls
  `Main.open_travel()`, which opens `ui/travel_menu.tscn` (`TravelMenu`: the Hollow plus every
  region whose waystone is awake, from `WorldMap.travel_stops()`; picking one calls
  `Main.travel_to()`); a Region stone is also a checkpoint; each kind and color has its own
  rune, unlike any checkpoint's), `crumble_platform` (`@tool`, width in tiles),
  `sinking_leaf` (one-way, sinks while stood on; speed and depth per instance), `push_block`
  and `stone_block` (the boulder
  version), `shortcut_gate` (opens from one side, saved as a flag), `color_gate` (rock wall
  that falls when its color returns, showing a faint trace until then), `color_orb`,
  `thorns` (`@tool`: a row of thorns with `length` in tiles plus `adjust_px`, `direction`, and `tint`; origin at its
  first tile's top-left), `spirit_gate` (`@tool`, class `SpiritGate`, a Spirit Room's gate;
  origin at the bottom center of its doorway; `mode` Entrance leads to `target_room`, Exit leads
  back and stays dark until the room's color is taken; used with Interact in the `Doorway`,
  which shows a `Hint` with the key. Parts: `Stone` (one image, `art/gate/spirit_gate.png`, with
  the doorway at `opening`), `Portal` (glow shader, behind the stone's doorway), `Runes` (`Rune`
  nodes: glyph from `glyph_sheet`, carved groove, pulsing light), `Motes`; the gate sets the
  colors), `message_trigger`
  (prompt text; `{time}` and `{deaths}` fill in), `dash_ember`, `leaf_fall` (Ember Grove's
  falling leaves).
- **Milestone 4 set** (each `@tool` and sized in tiles where it makes sense; see the tables in
  `docs/BUILDING_ROOMS.md`): hazards `water`, `stalactite` and `falling_log` (both
  `FallingHazard`), `rolling_logs`; objects `one_way_platform`, `swaying_branch`,
  `bounce_flower`, `pressure_plate` + `plate_door` (plates call `set_active()` on their
  `targets`), `breakable_wall`, `wind_gust`, `waterfall`, `vines`, `spirit_barrier`; creatures
  `bee`, `boar`, `snail` (extends `PushBlock`: its hidden shell is one), animated with
  `SheetAnim` from `art/creatures/`. Creatures and falling things kill through a `Hurt` Area2D
  on the hazards layer and check hazards with shape queries that exclude their own.
  Everything that kills joins the `hazards` group (painted on the hazards color layer);
  everything that moves joins `room_reset`.
- **Test rooms:** `rooms/test/movement_test.tscn`, the movement stations, built from its own
  text layout with the grey test tileset (F9 with the overlay showing); and
  `rooms/test/gallery.tscn`, every hazard, object, and creature in a row, with signs (F10).

## Conventions

**GDScript**
- Static typing everywhere: typed vars, parameters, and return types (`-> void`). Use `:=`
  when the type is obvious.
- Tabs for indentation, two blank lines between functions, `##` doc comments on classes and
  exported members.
- Files and folders `snake_case`; `class_name` in `PascalCase`; constants `UPPER_SNAKE`;
  signals named in the past tense (`died`, `color_unlocked`); `StringName` literals (`&"idle"`)
  for animation and action names.
- No movement numbers in code. Every tunable value goes in `PlayerTuning` (or exports on the
  thing it tunes), so an assist mode can change them later.
- Hand-written movement on CharacterBody2D with `move_and_slide()`; no RigidBody for the hero.
- The hero's hazard box is its collision box shrunk 2 px at the sides and feet, but reaching
  4 px above it to the top of the drawn head when standing (`hurtbox_head_reach`), so a head
  touching thorns dies.
- Triggers confirm the hero really overlaps them with `Touch.hero_in()` before acting (see
  the gotchas).

**Scenes and resources**
- Keep scenes and resources as text (`.tscn`, `.tres`) so they can be read and diffed.
- Commit `.import` and `.uid` files; never commit `.godot/`.
- Nodes `PascalCase` (`Sprite`, `Body`, `Spawns`). Entities place by a clear origin: feet or
  bottom center for things that stand, top-left for ledges and walls on the tile grid.

**Art**
- 16×16 tiles. Hero frames are 48×48 with the feet at y = 40 of the frame, so the `Sprite`
  sits at (0, -16) and the player node's origin is at its feet. Origin at the feet for every
  character.
- All hero sheets face right; flip with `flip_h` for left. `wall_slide` and `wall_land` are
  drawn with the wall on the hero's right.
- Game art is built by `python tools/build_art.py` from the Legacy-Fantasy forest pack: the
  terrain is cut so the ground the hero stands on is on the 16 px grid (grass: the dark soil,
  with the grass blades drawn as "grass top" tiles in the cell above, behind the hero, by
  `TerrainLayout`'s `grass_tops` layer; rock: the top of the boulders), and all 16 edge
  combinations are composed from quarter tiles. Hand-painted terrain gets no grass tops. Change art there and rerun, don't edit `art/`.
  (`art/hero/` and `art/tilesets/test_tiles.*` are the exceptions: copied/made earlier; so is
  `art/gate/`, the Spirit Gate's stone and glyph sheet, which @Ben repaints by hand.)
- No grey copies of sprites; shaders handle grey. Leave behind the samurai pack, weapon and
  punch animations, city backgrounds, and the forest pack's own hero.
- Palette-sensitive art: any new hero color must keep its body part's hue band.
- **Text:** drawn at the screen's full resolution, not 480×270, so it's smooth and easy to read.
  Every Control uses `ui/theme.tres` (the project theme): Nunito Bold (`art/fonts/nunito.ttf`)
  at size 9 in game units (27 px on a 1080p screen). Use the theme rather than overriding the
  font on new text. The font's license (`art/fonts/OFL.txt`) must ship with the game.
- **Scaling:** `window/stretch/mode` is `canvas_items` (integer scale) so text renders at full
  resolution. That lets things draw between the art's pixels, so anything that moves snaps its
  drawing to whole game pixels (`Player._process`, the spirit, leaves, push blocks; the camera
  and backdrop round their positions). Do the same for new moving art.

## Running and checking

- **Play:** open `project.godot` in Godot 4.7.x and press F5, or run `godot --path .`.
- **Errors without a window:** `godot --headless --path . --import` reimports and reports
  errors; `godot --headless --path . --quit-after 60` runs the game briefly (it autosaves to
  slot 1, so add `-- --slot=9`).
- **Tests** (all headless; exit code = failures; run all five after any gameplay change):
  - `godot --headless --path . --fixed-fps 60 res://tests/run_tests.tscn`: movement rules and
    the level-building numbers (update the table in `docs/DESIGN.md` when they move).
  - `... res://tests/game_systems.tscn`: world map vs rooms, checkpoints, Spirit Room restarts,
    crumbling ledges, leaves, region color, the door, pause/settings/map menus, save round-trip.
  - `... res://tests/hazards.tscn`: every hazard, object, and creature, tried in the gallery.
  - `... res://tests/slice_playthrough.tscn`: a bot plays the whole slice start to finish. When
    a room changes, update its route; a failing leap usually means a jump got too hard.
  - `... res://tests/meadow_playthrough.tscn`: a bot plays Sunlit Meadow with orange returned,
    through its Spirit Room to yellow, every move a list of timed presses. `-- --from=<room>`
    starts at a later room, `-- --trace` prints the hero's path frame by frame (and what killed
    it). Rooms are tight on purpose, so after moving anything, rerun it and retime the route.
- **Screenshots without playing:** `godot --path . --write-movie out.png --fixed-fps 60
  --quit-after 30` writes 480×270 PNG frames.
- Feel can't be checked automatically; after movement or level changes, ask @Ben for a
  playtest and take feel notes literally ("the jump floats at the top").

**Godot gotchas found the hard way**
- An Area2D never reports tile collision layers (both count as static to the physics engine).
  Check hazards and vines with direct shape queries, as `Player._overlaps()` does.
- For one frame after a room loads, an Area2D can report the hero inside it from stale
  positions. Every trigger double-checks with `Touch.hero_in()`.
- `godot -s script.gd` compiles the script before autoloads exist, so anything touching
  `GameState` fails. Run test code as a scene instead.
- `Input.action_press()` made inside a physics frame counts as "just pressed" only on the next
  frame, and it never reaches `_unhandled_input`. Tests press buttons between frames (they step
  on `process_frame`); UI that must react to them polls `Input.is_action_just_pressed()`.
- Timers count down in floating point: compare against `Player.EPSILON`, not 0.
- Headless runs use a dummy audio driver that never finishes a sound (reported as leaks at
  exit), so `Sfx` stays silent there.
- A sync_to_physics AnimatableBody2D (the sinking leaf) can't be teleported by setting its
  position: the physics step replays the move as fast motion (flinging the hero) or overrides
  it. Switch sync off for the frame of the teleport, as `SinkingLeaf._teleport_to_start` does.
- A thing wedged exactly flush under a ceiling can't slide: leave a tile of headroom over push
  blocks.
- A one-way shape made in code (`shape_owner_set_one_way_collision`) has a margin of 0, and
  nothing lands on it; set `shape_owner_set_one_way_collision_margin(owner, 1.0)` (a
  CollisionShape2D's default).
- A scene whose script fails to parse runs as an empty scene forever, and its output is lost
  when it's killed: run tests under a timeout, writing output to a file. A check that errors
  mid-run never returns either, so the hazards suite quits itself after 5 minutes.
- Don't name a method `_get`, `_set`, or `_init` by accident: they're Object virtuals.
- `reload_current_scene()` and `change_scene_to_file()` take the current scene out of the tree
  at once, so code after them in the same function has no viewport or tree (`get_viewport()` is
  null). Finish everything, such as `set_input_as_handled()`, before calling them.

## Workflow

- **Version:** bump the patch number of `application/config/version` in `project.godot`
  (1.0.12 → 1.0.13) after every requested change, so @Ben can tell builds apart. It shows in the
  bottom-right corner.
- Small steps: one feature, one playtest, one commit, so any change can be rolled back.
- Commit and push only when asked.
- Licenses for Asset Packs 1–5 and the Legacy-Fantasy pack must be confirmed before any paid
  release (see `docs/DESIGN.md`).
